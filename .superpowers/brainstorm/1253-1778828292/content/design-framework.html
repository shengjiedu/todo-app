2. 数据模型设计

Task 表结构
Task {
  id:           string (UUID)
  title:        string           // 任务名称
  description:  string|null      // 备注
  scheduledDate: date            // 安排日期 (YYYY-MM-DD)
  startTime:    string           // "08:00"
  endTime:      string|null      // "10:00" (可选)
  brainTokens:  integer          // 人脑 Token 消耗
  intensity:    enum             // low | medium | high | extreme
  priority:     integer          // 1-5，用于重排
  status:       enum             // pending | completed | cancelled
  autoRollover: boolean          // 未完成时是否顺延
  createdAt:    datetime
  updatedAt:    datetime
}

// 每天 8 点定时任务的逻辑：
// 1. 查询 scheduledDate = 今天 且 status = pending 的任务
// 2. 将这些任务的 scheduledDate 改为明天
// 3. 重新计算 startTime（按 priority 排序，均匀分布在 6-22 点）
// 4. 生成新的 schedule 记录
// 5. 推送 WxPusher 消息

4. 定时任务流程

22:00 提醒流程 & 08:00 重排流程
22:00 晚间提醒：
  ├─ 检查明天是否有已安排任务
  ├─ 若无 → 推送："📋 明天还没有安排任务哦，快来规划一下"
  └─ 若有 → 推送："📋 明日待办已就绪（4个任务，共 670 token）"

08:00 早间重排：
  ├─ 查找今天 status=pending 的任务
  ├─ 将这些任务 scheduledDate 改为明天
  ├─ 按 priority 重新分配时间段（6:00-22:00 均匀分布）
  ├─ 检查是否有任务连续顺延超过 3 天 → 标记为高优先级
  ├─ 生成新的每日计划
  └─ 推送 WxPusher：
      "📅 5月15日待办（顺延2个/新增0个）
       1. 看钙钛矿论文 08:00 🧠50
       2. 组会汇报准备 10:00 🧠120
       ...
       今日预算：670/1000 token"

5. 手机端适配策略

响应式断点设计
桌面端 (≥1024px):
  ├─ 左右分栏：左侧时间轴(280px) + 右侧任务列表(flex:1)
  └─ 完整显示所有信息

平板端 (768px-1024px):
  ├─ 左右分栏但时间轴缩窄(200px)
  └─ 任务卡片简化显示

手机端 (<768px):
  ├─ 单栏布局，底部 Tab 切换
  │   Tab1: 时间轴视图（垂直滚动）
  │   Tab2: 任务列表视图
  │   Tab3: 设置
  ├─ 添加任务用底部 Sheet 弹出
  └─ Token 预算显示在顶部胶囊条

6. 技术栈确认

前端 (复用现有):
  • React 18 + Vite + Tailwind CSS
  • 新增: react-router-dom (路由), dayjs (日期), framer-motion (动画)

后端 (复用现有):
  • Express.js + better-sqlite3 (同步 SQLite，适合单机)
  • 新增: node-cron (定时任务), axios (WxPusher API)

数据持久化:
  • SQLite 单文件数据库 (todo.db)
  • 备份: 每天 08:00 自动导出 JSON 到 backup/ 目录

外部服务:
  • WxPusher (你已有的推送渠道)
